## Цель

Добавить на странице `/technical-audit` подменю (Tabs) с двумя вкладками:
1. **Технические проверки** (текущий аудит краулером) — без изменений.
2. **Яндекс Вебмастер** — порт из проекта Analytics Start: 4 группы (Фатальные / Критичные / Возможные / Рекомендации), 37 проверок, сводные карточки, фильтры, виджеты индексации/запросов/ссылок.

## Контекст переноса

Исходник `Analytics Start/src/components/project/YandexWebmasterTab.tsx` завязан на:
- `projects` (url, seo_specialist_id), `integrations`, `team_members`
- таблицы `site_health` и `site_errors` (Яндекс заполняет edge-функция)
- edge-функции `yandex-webmaster` (OAuth + получение хостов) и `fetch-site-health`
- компоненты `DataStatusBadge`, `CreateTaskFromSourceButton`, `useSourceTasks`

В текущем проекте «SEO-Аудит» нет сущности «проект клиента» и нет OAuth-инфраструктуры Яндекса, аудит работает по домену.

## План реализации

### 1. UI-каркас (всегда делаем)
- В `src/pages/TechnicalAuditPage.tsx` обернуть содержимое после формы домена в `Tabs`: «Технические проверки» (текущий `TechnicalAuditView`) и «Яндекс Вебмастер».
- Создать `src/components/audit/YandexWebmasterView.tsx` — упрощённая версия исходного компонента: header, 4 summary-карточки, статус-баннер, фильтры (Все/Только ошибки/Фатальные/Критичные), поиск, 4 секции `Collapsible` с 37 проверками из `buildChecks(domain)`, виджеты индексации/запросов/ссылок. Дизайн — текущая дизайн-система (semantic tokens, без хардкода цветов в JSX, заменить `#F44336` и т.п. на `hsl(var(--destructive))`, `hsl(var(--chart-4))` и т.д.).
- Без `CreateTaskFromSourceButton` (нет задач в проекте) и без `DataStatusBadge`.

### 2. Источник данных
Здесь нужно решение пользователя — на скрине у CRM-проекта данные тянутся из БД, заполненной edge-функцией. У нас этой инфраструктуры нет. Варианты:

**A. Mock / пустое состояние** (рекомендуется как первый шаг): все проверки в статусе «Не проверено», блок «Нажмите Обновить данные …» с дисейбленной кнопкой и заглушкой «Интеграция с Яндекс.Вебмастером появится позже». Все 37 проверок и UI готовы — но без живых данных.

**B. Полная интеграция с Яндекс.Вебмастером**: нужно:
- завести OAuth-приложение Яндекса (Client ID/Secret — secrets);
- таблицы `wm_health` и `wm_errors` (по домену пользователя);
- 2 edge-функции: `yandex-webmaster` (OAuth callback + список хостов) + `fetch-yandex-webmaster` (тянет diagnostics + indexing + search-queries и пишет в БД);
- UI авторизации в Я.Вебмастер, выбор хоста для текущего домена.
Это полноценный отдельный проект на 1–2 итерации.

### 3. Что сделаем сразу
В рамках текущего запроса — пункт **1 + вариант A**: добавим вкладку и весь UI с заглушкой и кнопкой «Обновить данные» (отключена с подсказкой). Когда подтвердите выбор источника — реализуем вариант B отдельной задачей.
